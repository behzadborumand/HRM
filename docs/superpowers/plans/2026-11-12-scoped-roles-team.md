# Scoped roles and direct-manager workflow
Continue authorized native implementation in D:/SourceCodes/GitProjects/HRM on rewrite/modular-monolith; legacy HRMS_BHR read only.

## Design
Legacy Role has name/description/permission list; legacy Leave approval verifies current direct-manager relationship. Add company-owned AccessRole with Name,Description,Active,CanReadEmployees,CanWriteEmployees,CanManageTeam and RowVersion. User has nullable RoleId with same-company composite FK. Existing explicit read/write flags are preserved and combined with active role grants; role write implies read. Administrator remains a protected account property, never granted by custom role. No broad/department access is inferred from manager linkage. Full permission catalog/department grants remain a later slice.

Administrator Roles page creates/edits/archives roles and assigns one role per user in existing Users page. Grant changes/archive atomically update assigned users' rowversions so old cookies expire; account role reassignment already changes user rowversion. An inactive role supplies no grants. Assignment validates company and requires employee link for a manager role.

A team permission plus active same-company employee link allows only active direct reports from same-company current EmployeeJobs. Personnel owns relationship queries, basic profile/job/photo authorization and paginated team list. Owner/general grants keep current behavior. Managers get no pay, documents, private profile activity, employee edits, organization/catalog or company-report permission through this role.
Team Leave queue is a read-only Reporting projection joining current Personnel scope and Leave, paginated20 and excludes private reason/comments. Decisions go through Leave service, recheck current relationship, prohibit self-approval, require exact request rowversion for managers, retain actor/time and serializable balance/retry rules. Relationship changes take effect on next query. No cross-module writes.
