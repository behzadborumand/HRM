# Data migration contract

The destination is a separately named, configurable SQL Server database. Never point the transfer tool or migrations at the production legacy database. The legacy `dbo` schema is read only.

| Legacy source | Destination owner | Key rule |
| --- | --- | --- |
| `dbo.Companies`, `dbo.Departments` | Organization | Preserve source IDs in an import map |
| `dbo.Employees`, `dbo.EmployeePersonalInfo`, `dbo.EmployeeJobs` | Personnel | Map employee IDs, retain administrative dates as dates |
| `dbo.Users`, `dbo.Roles` | Access | Rehash or force credential reset after algorithm review |
| `dbo.TimeOff*` | Leave | Map employee and policy IDs; compare balances |
| `dbo.Training*` | Training | Map course and employee IDs |
| `dbo.EmployeeDocuments` and private files | Documents | Copy after verifying file existence and checksums |

Each import batch must upsert by stable legacy source key, record mapping, and produce source/destination counts, missing or duplicate keys, orphan references, invalid dates, and changed-value differences. A rerun must produce no additional rows. Trial execution and reconciliation on a disposable database are required before any operational transfer. The transfer tool is not yet implemented.

Initial idempotent schema scripts were generated for review in `next/access-initial.sql`, `next/organization-initial.sql`, and `next/personnel-initial.sql`. They were generated by EF Core 9 because SDK 10 is absent; regenerate and validate with EF Core 10 before applying them. No script was executed against SQL Server. The existing `sql/02_Create_Tables.sql` drops legacy tables and must never be used for this transfer.
