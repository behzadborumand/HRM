# Data migration contract

The destination is a separately named, configurable SQL Server database. Never point the transfer tool or migrations at the production legacy database. The legacy `dbo` schema is read only.

| Legacy source | Destination owner | Key rule |
| --- | --- | --- |
| `dbo.Companies`, `dbo.Departments` | Organization | Preserve source IDs in an import map |
| `dbo.Employees`, `dbo.EmployeePersonalInfo`, `dbo.EmployeeJobs` | Personnel | Map employee IDs, retain administrative dates as dates |
| `dbo.Users`, `dbo.Roles` | Access | Rehash or force credential reset after algorithm review |
| `dbo.TimeOff*` | Leave | Map employee and policy IDs; compare balances |
| `dbo.Training*` | Training | Map course and employee IDs |
| `dbo.EmployeeDocuments` and private files | Documents | Copy after verifying file existence and checksums |

Each import batch must upsert by stable legacy source key, record mapping, and produce source/destination counts, missing or duplicate keys, orphan references, invalid dates, and changed-value differences. A rerun must produce no additional rows. Trial execution and reconciliation on a disposable database are required before any operational transfer. The core transfer script is implemented; other legacy tables and fields remain to be mapped. The separate Leave schema script is `database/leave-initial.sql`, generated with EF Core 9 pending EF Core 10 regeneration. It was applied twice to the disposable trial database; Leave has 3 business tables, 1 migration history table, and 2 policy foreign keys.

Initial idempotent schema scripts were generated for review in `database/access-initial.sql`, `database/organization-initial.sql`, and `database/personnel-initial.sql`. They were generated by EF Core 9 because SDK 10 is absent; regenerate and validate with EF Core 10 before operational use. On 2026-11-08, the scripts were applied and rerun only in the new `HRMS_Next_Trial_20261108` database. Migration histories contain Access 1, Organization 2, Personnel 1. Organization foreign keys and Personnel rowversion were verified. One real SQL employee flow test and an HTTPS login/create/edit smoke test passed and removed their test rows. The legacy `sql/02_Create_Tables.sql` in the separate HRMS_BHR source project drops tables and must never be used for this transfer.

`database/import-core.sql` reads only `HRMS_BHR.dbo` on the same SQL Server and writes only to a destination whose name starts `HRMS_Next_`. Run it with `sqlcmd -S . -E -C -b -d HRMS_Next_Trial_20261108 -i database/import-core.sql` after applying the schema scripts. It records legacy-to-destination IDs in `migration` map tables, checks missing/duplicate references, reports source versus mapped counts and changed rows, and does not overwrite mapped values on rerun. The trial imported 1 company, 5 departments and 12 employees twice with zero invalid or changed rows. It has not transferred job history, personal information, users, roles, documents, leave, training, or sensitive fields.
