# پیاده‌سازی مدارک و اسناد کارکنان (فاز ۱۱)

## وضعیت: تکمیل شده و تست شده روی اپ در حال اجرا

### معماری
```
Views/Documents/Index.cshtml  →  DocumentsController  →  DocumentService  →  IRepository<EmployeeDocument>  →  HrmsDbContext  →  SQL Server (HRMS_BHR)
                                             ↘  App_Data/uploads/{employeeId}/{guid}.ext  (فایل روی دیسک)
```

### اکشن‌ها
| مسیر | متد | دسترسی لازم | توضیح |
|---|---|---|---|
| `/Documents?employeeId={id}` | GET | مالک پرونده یا `employees.read` | فهرست مدارک + فرم بارگذاری |
| `/Documents/Upload` | POST | `employees.write` | `multipart/form-data` با سقف حجم ۲× حد مجاز فایل |
| `/Documents/Download/{id}` | GET | مالک پرونده یا `employees.read` | `PhysicalFile` با نام اصلی فایل |
| `/Documents/Delete` | POST | `employees.write` | حذف رکورد و فایل |

لینک ورود از هدر صفحه پرونده کارمند (`مدارک`) است؛ صفحه مستقل طراحی شد چون آپلود چندفایلی و فهرست، جا در فرم موجود پرونده نداشت.

### تصمیم‌های ایمنی
- **خارج از wwwroot:** فایل‌ها زیر `App_Data/uploads` می‌نشینند، پس به‌صورت استاتیک سرو نمی‌شوند و هر دانلود از کنترل دسترسی کنترلر رد می‌شود.
- **نام فایل تولیدی:** مسیر دیسک همیشه `{employeeId}/{Guid:N}.ext` است؛ نام اصلی کاربر فقط در ستون `FileName` برای نمایش و `Content-Disposition` نگه داشته می‌شود، بنابراین یک نام مخرب (مثل `..\..\web.config`) روی سیستم فایل اثر ندارد.
- **دفاع دوم در دانلود:** مسیر نهایی با `GetFullPath` بررسی می‌شود و اگر بیرون از ریشه `uploads` باشد یا فایل موجود نباشد، `NotFound` برمی‌گردد.
- **پسوندها و حجم:** `DocumentRules` تک‌منبع قوانین است (Core، بدون وابستگی به HTTP) تا هم سرویس و هم ویو از آن بخورند و در آزمون واحد پوشش داده شود.
- **حذف کارمند:** تا وقتی کارمندی سند دارد، حذف او با پیام راهنما متوقف می‌شود؛ حذف فایل‌ها بی‌صاحب یا بی‌اخطار انجام نمی‌شود.

### نکات تست
- ورود تاریخ انقضا از همان `JalaliDateModelBinder` فاز ۱۰ استفاده می‌کند؛ تست HTTP با `۱۴۰۶/۰۲/۱۰` مقدار `2027-04-30` ثبت کرد.
- آپلود با `-F` (multipart) انجام می‌شود؛ توکن anti-forgery هم باید به‌عنوان یک فیلد فرم ارسال شود، نه هدر.
- فایل‌های تستی داخل `App_Data/uploads` پس از هر صحت‌سنجی پاک می‌شوند؛ این پوشه در `.gitignore` است.
